基礎知識：対数の理解度チェック

🧩 対数クイズ

情報量の学習には対数の基本的な理解が必要です。以下のクイズで確認してみましょう。

問題1: log₂ 8 = ?

問題2: log₂ (1/4) = ?

問題3: 2ˣ = 16 のとき、x = ?

正解数: 0/3

📚 段階的導入：なぜ対数なのか？

情報量の定義に対数が使われる理由を、段階的に理解していきましょう。

ステップ1: 「珍しさ」と「情報量」

日常生活で考えてみると：

  • 教材で雨の確率を30%と設定すると、雨が降ったときの情報量は約1.74bit
  • 教材で出来事の確率を0.001%と設定すると、情報量は約16.61bit
  • 確実に起きるとモデルで仮定した出来事の情報量は0bit

つまり、同じモデルで確率が低いほど情報量が大きいと定義します。内容の重要性や感情的な驚きとは別の尺度です。

ステップ2: 独立事象の組み合わせ

2つの独立した出来事が同時に起こる場合を考えてみましょう：

  • コインで表が出る（1/2）+ サイコロで6が出る（1/6）
  • 同時に起こる確率：1/2 × 1/6 = 1/12
  • 情報量に「足し算」を要求する：I(表) + I(6) = I(表かつ6)

確率は「掛け算」、情報量は「足し算」になるような関数が必要です。

ステップ3: 対数の性質

対数には重要な性質があります：

  • log(a × b) = log(a) + log(b)
  • これで確率の積→情報量の和に変換できます
  • P(A∧B) = P(A) × P(B) → I(A∧B) = -log(P(A) × P(B)) = -log(P(A)) - log(P(B)) = I(A) + I(B)

だから情報量は I = -log P の形になるのです！

情報量の定義

🌟 豊富な直感例

📰 ニュース・メディア

  • ニュースのたとえ：「犬が人を噛んでもニュースにならないが、人が犬を噛んだらニュースになる」→ めったに起きないほど情報量が大きい
  • スポーツ：教材で「王者が勝利」を70%、「大番狂わせ」を5%と設定すると、後者の情報量が大きい
  • 芸能：「人気俳優の結婚発表」→ 予想外度が高いほど話題性が大きい

🎲 ゲーム・確率

  • コイン投げ：「表が出た」(50%) より「立った」(0.01%) はまれ → 情報量が大きい
  • サイコロ：「1が出た」(1/6) より「連続で6回とも1の目」(1/6⁶) → 後者は驚異的
  • 宝くじ：「はずれ」は当たり前、「1等当選」は人生を変える情報

🌤️ 日常生活

  • 天気：「晴れの日に雨」→ 予報が外れると情報価値が高い
  • 交通：「電車が定刻」は当然、「大幅遅延」は重要情報
  • メール：「スパム」vs「重要な連絡」→ 情報量は、モデルでの確率の逆数の対数

💡 学習・発見

  • 試験結果：「予想通りの点数」vs「予想外の高得点/低得点」
  • 科学的発見：「既知の法則通り」vs「新しい現象の発見」
  • AI予測：「高確信度の予測」vs「低確信度だが的中」→ 設定した確率が低いほど情報量が大きい

🔑 重要な洞察

情報の価値 ≠ 情報量：受け手にとっての「価値」と、確率にもとづく「情報量」は区別して考える必要があります。情報量は選んだ確率モデルから計算する尺度で、価値とは別です。例の確率は教材用の設定値です。

シャノンの定義

事象 a の生起確率を P(a) とすると、情報量 I(a) を

I(a) = - log₂ P(a)

と定義する（単位：bit）。

  • 非負：0 < P ≤ 1 なので I ≥ 0
  • 単調減少：めったに起きないほど値が大きい
  • P=1でI=0：確実な事象は情報量ゼロ

I = -log₂ P のグラフ

横軸: P (0<P≤1), 縦軸: I=-log₂P。上限16bitを超える部分は枠外です。

📊 このグラフの見方

  • 曲線の特徴：確率が小さいほど情報量が急激に増加
  • 重要なポイント：P=0.5で1bit、P=0.25で2bit、P=0.125で3bit
  • 実感のコツ：確率が半分になるたび情報量が1bit増える

比較：y=ax / y=x / y=logₐx

y = ax y = x y = logₐ x

🔧 操作方法

底aを変更して3つの関数の関係性を比較できます。

  • 指数関数（青）：急激に増加、y=aˣ
  • 一次関数（黄）：直線的増加、比例関係
  • 対数関数（水色）：緩やかに増加、y=logₐx

a>1のとき、指数と対数は互いに逆関数です。表示範囲の外側は省略しています。

    加算性：独立事象が同時に起きたときの情報量
    

      
    
        
    なぜ I(a) = -log₂ P(a) なのか
    
        
    情報量の定義がこの形になる理由の一つは、加算性を満たすためです。
    
        
    独立事象 A, B が同時に起きたとき：
    
        
      
          
    • 確率は積：P(A∧B) = P(A) × P(B)
      • 
          
    • 情報量は和：I(A∧B) = I(A) + I(B)
      • 
        
    
        
    単調性も仮定すると、この関係を満たす関数は対数関数 -log P の形に限られます（定数倍を除く）。
    
        
    つまり、「独立な情報の組み合わせは、それぞれの情報量の足し算になる」という自然な要請から、シャノンの定義が導かれるのです。

    確率が大きいほど情報量は小さく、確率が小さいほど情報量は大きい。

              P = 0.0001 → I = 13.3 bit
    
              「宝くじレベル」
            
    
          
    
        
    
      
    

      
    
        
    ⚡ 連続性（Continuity）
    
        
    0<P≤1の各点で連続です。ただしPが0に近いほど変化率は大きく、確率差だけから情報量差の大小は決まりません。
    

        
    
          
    
            
    
              
              
    I₁ = 1.0000 bit
    
            
    
            
    
              
              
    I₂ = 0.9710 bit
    
            
    
          
    

          
    
            
    
              確率差：|P₂ - P₁| = 0.0100
            
    
            
    
              情報量差：|I₂ - I₁| = 0.0290 bit
            
    
            
    
              
            
    
          
    
        
    

        
    
          
    🔧 連続性の確認方法
    
          
    0.5と0.51、0.0001と0.0101を比べてください。確率差が同じでも情報量差は異なります。
    
        
    
      
    

      
    
        
    ➕ 加法性（Additivity）
    
        
    独立事象A, Bについて、I(A∧B) = I(A) + I(B) が成り立つ。
    

        
    
          
    🎲 実例：サイコロ＋コイン
    
          
    
            
    
              
    事象A：サイコロで6が出る
    
              
    P(A) = 1/6 ≈ 0.1667
    
              
    I(A) = 2.58 bit
    
            
    
            
    
              
    事象B：コインで表が出る
    
              
    P(B) = 1/2 = 0.5000
    
              
    I(B) = 1.00 bit
    
            
    
            
    
              
    事象A∧B：両方同時に起こる
    
              
    P(A∧B) = P(A) × P(B) = 0.0833
    
              
    I(A∧B) = 3.58 bit
    
              
    
                検証：I(A) + I(B) = 3.58 bit ✅
              
    
            
    
          
    

          
    
            
    🔧 カスタム検証
    
            
    
              
    
                
                
    I(A) = 1.74 bit
    
              
    
              
    
                
                
    I(B) = 1.32 bit
    
              
    
              
    
                
    P(A∧B) = 0.12
    
                
    I(A∧B) = 3.06 bit
    
                
    I(A) + I(B) = 3.06 bit
    
                
    
              
    
            
    
          
    
        
    
      
    

      
    
        
    📏 規格化（Normalization）
    
        
    基準を決めることでスケールが定まる。通常「P=1/2の事象の情報量を1bit」とする。
    

        
    
          
    🎯 異なる基準での比較
    
          
    
            
          
    

          
    
            
    
              
    P = 1/2 の情報量
    
              
    1.000 bit
    
            
    
            
    
              
    P = 1/4 の情報量
    
              
    2.000 bit
    
            
    
            
    
              
    P = 1/10 の情報量
    
              
    3.322 bit
    
            
    
          
    

          
    
            
    重要：基準が変わっても相対的な関係は保たれます。P=1/4の情報量は常にP=1/2の2倍です。
    
          
    
        
    
      
    
    
    

    
    
    
      
    エントロピー・応用：平均情報量と実世界での活用
    

      
    
        
    📊 エントロピー（平均情報量）の定義
    
        
    情報源 X の 平均的に得られる情報量（期待値）であり、分布の不確定さの尺度：
    
        
    H(X) = - Σ P(xᵢ) log₂ P(xᵢ)
    
        
      
          
    • 均等分布ほど不確定さが大きい → エントロピーが大きい
      • 
          
    • 確実（1つに集中）なら不確定さがない → エントロピー 0
      • 
        
    

        
    
          
    エントロピー計算器（最大4事象）
    
          
    
          
    
            
    
            
    
            
    
            
    
          
    
          
    
            合計 P = 1.0000
            ※ 合計が 1 ではありません
          
    
          
    
            
    
              
    エントロピー H(X)
    
              
    —
    
              
    
            
    
            
    
              
    ヒント
    
              
      
                
    • 均等：H が最大（例：4事象なら 2 bit）
      • 
                
    • 集中：H が小さい（極端には 0）
      • 
              
    
            
    
          
    

          
    
          
    
            
    ⚙️ エントロピー計算器の使い方
    
            
      
              
    • 確率分布の設定：4つまでの事象について確率を設定（合計1）
      • 
              
    • リアルタイム計算：入力と同時にエントロピーと計算過程を表示
      • 
              
    • 分布の比較：均等分布（0.25, 0.25, 0.25, 0.25）vs 偏った分布（0.7, 0.2, 0.1, 0）で違いを実感
      • 
              
    • 応用理解：データ圧縮や暗号強度の理論的基盤を数値で体感
      • 
            
    
          
    
        
    

        
    
          
    🛡️ エントロピーと攻撃の関係
    
          
    N個の候補が等確率で、重複なく1個ずつ試して正解を判別できるモデルでは、H=log₂N、平均試行回数=(N+1)/2です。
    
          
    一般の偏った分布では、Shannonエントロピーだけから平均試行回数は決まりません。攻撃時間には方式と1秒あたりの試行回数などの条件も必要です。
    
        
    
      
    

      
    
        
    💾 データ圧縮の原理
    
        
    情報量とエントロピーは、データ圧縮の理論的基盤です。
    

        
    
          
    教材用の1000文字から一部を抜粋した例
    
          
    
            
    
              
    
                
    文字頻度確率情報量⌈情報量⌉の例
    
                
    E12712.7%2.98 bit3 bit
    
                
    T919.1%3.46 bit4 bit
    
                
    A828.2%3.61 bit4 bit
    
                
    Z10.1%9.97 bit10 bit
    
              
    
            
    
            
    原理：頻出文字ほど短い符号、稀な文字ほど長い符号を割り当てることで、全体の平均符号長を最小化。
    
            
    理論限界：離散情報源の一意復号可能な符号では平均符号長 ≥ エントロピー。表は完全な分布やHuffman符号の割り当てではありません。
    
          
    
        
    

        
    
          
    身近な圧縮技術
    
          
      
            
    • ZIPのDEFLATE：LZ77 + Huffman符号
      • 
            
    • JPEG：DCT変換 + 量子化 + エントロピー符号化
      • 
            
    • MP3：心理音響モデル + 適応的量子化
      • 
            
    • 言語モデル：正解トークンの予測確率を高めるクロスエントロピー損失を利用
      • 
          
    
        
    
      
    

      
    
        
    🔐 暗号学での情報量
    
        
    鍵の不確実性と、暗号を破るための計算量は異なります。エントロピーだけでは暗号方式や実装の安全性を判定できません。

    🔐 文字列モデルの使い方
    
                  
      
                    
    • 文字数：パスワードの長さを設定
      • 
                    
    • 文字種類数：使用可能文字の総数（空白を含む印字可能ASCII文字=95、英数字=62等）
      • 
                    
    • エントロピー：各文字を独立に等確率で選ぶと仮定した不確実性
      • 
                    
    • 推測回数：候補を重複なく試し、正解を判別できる場合の平均(N+1)/2
      • 
                  
    
                  
    人が選んだ単語、再利用、偏りは評価しません。文字列そのものを入力する機能はありません。
    
                
    
              
    
            
    

            
    
              
    暗号アルゴリズム比較
    
              
    
                
    方式鍵長古典計算での安全強度の目安
    
                
    DES56 bit破綻済み
    
                
    AES-128128 bit128 bit
    
                
    AES-256256 bit256 bit
    
                
    RSA-20482048 bit112 bit
    
              
    
              
    NIST SP 800-57 Part 1 Rev.5の比較値です。安全性の保証や量子計算への耐性を示す表ではありません。
    
            
    
          
    
        
    

        
    
          
    完全秘匿性（Perfect Secrecy）
    
          
    シャノンが証明した理想的暗号の条件：
    
          
      
            
    • H(平文|暗号文) = H(平文)：暗号文から平文への情報漏洩ゼロ
      • 
            
    • 鍵エントロピー ≥ 平文エントロピー：十分なランダムネス必要
      • 
            
    • ワンタイムパッド：平文と独立な一様ランダムの鍵を平文と同じ長さだけ用意し、再利用しない場合の例。改ざんを検知する機能は別途必要
      • 
          
    
        
    
      
    

      
    
        
    🌡️ 物理学のエントロピーとの関係
    
        
    情報エントロピーと熱力学エントロピーは深い関係があります。
    

        
    
          
    
            
    
              
    共通点
    
              
      
                
    • 不確実性の尺度：確率分布を使った記述ができる
      • 
                
    • 対数的構造：S = k log W, H = -Σp log p
      • 
                
    • 加法性：独立系では和で表現
      • 
                
    • 注意：情報エントロピーが時間とともに必ず増えるという法則はない
      • 
              
    
            
    

            
    
              
    相違点
    
              
      
                
    • 対象：情報 vs 物理系
      • 
                
    • 単位：bit vs J/K
      • 
                
    • 物理系：可逆過程と不可逆過程の区別が必要
      • 
                
    • 前提：確率モデルと物理状態の対応を指定する必要がある
      •

    情報ボトルネック理論
    
          
    入力Xの表現Tに、目標Yの予測に必要な情報を残すという設計上の考え方です。すべての深層学習が次の段階を通るという意味ではありません。
    
          
      
            
    • 圧縮の目的：I(X;T)を最小化（入力の冗長性除去）
      • 
            
    • 予測の目的：I(T;Y)を最大化（出力との相関強化）
      • 
            
    • 最適解：圧縮と予測のトレードオフ
